SSD 自动化测试失败 AI 分析
与自进化系统

测试平台旁路部署的失败分析层：把「失败日志」变成「带证据链的根因结论 → 可机器复现的确证资产 → 可自我改进的分析策略」。 核心不是让 AI 读日志，而是用同批次对照归因与不可逆性边界检测分离 DUT 缺陷与测试环境误报，再以三通道自进化持续收敛。

Qoder Agent SDK Python 3.11 / FastAPI PostgreSQL + pgvector 钉钉通知闭环 内网 Linux 部署 日均千级 case

一、总体架构

七层结构 + 右侧知识资产库。左侧为数据自下而上的证据流，右侧为反馈与资产的回流通道，虚线为复现回路。

系统自有分层（L1–L6，旁路部署） 既有平台 / 外部系统 专利技术机制 M1–M4 复现回路（影子真机）

二、端到端闭环

一次失败从发生到系统变聪明的完整链路。底部回流通道是「自进化」的实际发生地。

三、六个技术机制（专利落点）

每一条都对应一个「技术问题 → 具体技术手段 → 可量化技术效果」的三段式，也是权利要求的撰写骨架。

M1双层失败指纹

把失败特征解耦为环境无关的症状签名与环境敏感向量，复合键决定资产适用边界，附环境兼容度打分控制结论迁移。

效果跨机器跨盘号聚合一致率 ↑，环境错配误判 ↓
M2同批次对照归因

以 DUT×环境构建 2×2 反事实对照网格，Beta-Binomial 收缩 + Fisher 显著性检验，把被测件缺陷与测试系统误报在统计上分离。

效果环境误报识别率 ≥ 85%
M3不可逆性边界

按事件可恢复性切分因果级联，定位首个不可恢复事件作为因果起点，替代"最后一条报错"的表层归因。

效果根因层级正确率 +20~35 pt
M4假设-复现-确证

生成结构化可执行复现配方 → 影子真机执行 → 症状签名匹配 → 置信度提升至 0.95+，把"AI 断言"升级为机器独立确证。

效果资产归档准入门槛可信
M5三通道自进化

规则蒸馏（零 LLM 快路径）· 策略 Bandit（求解链在线择优）· 测试资产反向生成（回归用例与预检脚本 PR），双闸门 + 灰度 + 回滚保障不退化。

效果重复问题成本 ↓90%，逃逸率 ↓
M6误判判别式挖掘

从每次被驳回的结论中差分提炼"防止此类错误的判别式"，升级为全局护栏并回放验证，避免过拟合。

效果重复误判率月降 ≥30%

四、关键前提与风险

架构能否兑现价值，取决于下面这一条工程前提是否被排期。

M0 关键路径：平台侧必须暴露拓扑与批次元数据

M2 同批次对照归因需要 bench_topology（主机 ↔ HBA ↔ 背板 ↔ 线缆 ↔ 温区映射）与 run_group_id（同批次标识）。 缺失时归因将退化为"单事件分析"，环境误报识别率从 85% 掉到约 55%，M1–M4 的价值同时受损。 这是 M0 阶段必须完成的平台改造项。

平台侧（既有）

  • 测试执行与结果展示
  • bench_topology 新增表
  • run_group_id 批次标识
  • 失败事件推送 API
  • AI 分析 Tab 嵌入位

分析服务侧（新建）

  • FastAPI 网关 · 3 副本
  • 解析 / 归因 / 进化 Worker
  • 复现影子调度器
  • LLMGateway 抽象层
  • 钉钉通知服务

存储层

  • PostgreSQL 16 + pgvector
  • HNSW 向量索引
  • MinIO 制品与日志
  • Redis 队列与语义缓存
  • 金标准集与版本血缘

外围与出口

  • 钉钉机器人 + 工作通知
  • Qoder Cloud（仅脱敏级）
  • 本地 CLI（涉密日志）
  • bench-agent 采集拓扑
  • Prometheus + Grafana
